# 小智 AI 与 AI8051U I2C 接口及协议说明

## 1. 目标

本文档用于说明当前 `xiaozhi-esp32` 与 `STC51/Project/ws2812_driver` 之间的本地 I2C 联调接口、默认时序、协议包格式，以及当前已实现和待验证的能力。

## 2. 当前接线与板级约束

### 2.1 ESP32 侧

- 活跃板型：`External/xiaozhi-esp32/main/boards/lichuang-dev`
- I2C SDA：`GPIO1`
- I2C SCL：`GPIO2`
- 矩阵从机地址：`0x31`
- 默认亮度：`0x40`

### 2.2 AI8051U 侧

- 工程路径：`STC51/Project/ws2812_driver`
- I2C 角色：从机
- I2C SCL：`P2.4`
- I2C SDA：`P2.3`
- 当前初始化中显式调用 `I2C_SwitchP2324()`，固定将 I2C 路由到 `P2.3/P2.4`，本项目连线约定为 `P2.4=SCL`、`P2.3=SDA`
- `P2.4/P2.3` 在初始化阶段被显式设置为开漏模式，并关闭内部上拉/下拉，空闲高电平仅由外接 `3.3V` 上拉电阻提供
- 从机地址：`0x31`

### 2.3 电平与上拉约束分析

- 当前主机侧为 ESP32，I2C 总线外接 `3.3V` 上拉电阻。
- 当前从机侧 AI8051U 工作在 `5V`，总线侧未额外接上拉电阻。
- I2C 为开漏结构，因此高电平最终由上拉电阻决定；在当前接法下，总线高电平会被拉到 `3.3V`。
- 这类接法是否“稳定可用”，关键取决于 AI8051U 在 `5V VCC` 下对 `3.3V` 高电平的输入判定门限。若器件或该引脚组没有明确给出 `3.3V` 兼容/TTL 阈值保证，则不能把当前直连方案视为强鲁棒方案。

当前结论：

- `短线、低速、样机阶段` 下，当前接法有概率正常通信。
- `量产或长期稳定运行` 不建议继续依赖该假设，硬件上更推荐增加双向电平转换，或把 AI8051U 侧 I2C 电平域统一到 `3.3V`。

本轮软件优化：

- ESP32 主机侧矩阵链路降到 `100kHz`，降低 `3.3V/5V` 混合场景下的边沿压力。
- ESP32 主机侧关闭内部上拉，明确依赖外接 `3.3V` 上拉电阻，避免并联上拉网络失控。
- AI8051U 从机侧 `P2.4/P2.3` 切换为开漏输出并关闭内部上拉，避免 5V 侧内部上拉把总线抬高。
- AI8051U 侧增加 USB I2C 状态日志，便于观察起停、收包长度、超时和溢出。

## 3. 启动联调行为

### 3.1 小智侧当前显示策略

当前版本取消了启动阶段自动 RGB 自检发送，矩阵链路改为“仅在显式图像更新时通信”：

- 语音颜色/效果命令触发一次 `SetAction`
- 同内容重复命令不再重复发送
- 设备进入待机、聆听、说话等状态时，不再自动向矩阵发送状态图案

目的：

- 避免共享 I2C 总线在无图像变化时被持续占用
- 避免待机状态把上一条语音图像覆盖为其他图案

### 3.2 AI8051U 侧默认回退图案

- AI8051U 上电后默认进入本地图案渲染路径
- 当前默认预设切换为渐变流动图案 `TEST_PRESET_CROSS_GRADIENT`
- 当远程模式被显式释放，或系统重新回到本地渲染路径时，矩阵会回到该默认渐变效果

### 3.3 在线/离线模式仲裁

- 离线模式：保持原先本地图案逻辑，`P32` 切换图案，`P33` 短按切换效果。
- 在线模式：由小智通过 I2C 协议命令控制矩阵显示，本地按键短按不再改写显示内容。
- 自动切换：AI8051U 侧收到并解析到有效小智协议包后进入在线模式；若连续一段时间没有新的有效通信，则回到离线模式。
- 手动切换：任意模式下长按 `P33`，可把当前模式切到另一模式；切回离线时会释放远程占用并恢复本地渲染。

说明：当前在线/离线自动切换依赖有效协议通信活动，而不是物理层“总线有抖动”本身；仅空 STOP 或无效包不会维持在线模式。

### 3.4 AI8051U I2C + DMA 接入说明

- 当前 AI8051U 侧已补充 I2C DMA 后端，寄存器使用遵循 `DMA_I2CT_*`、`DMA_I2CR_*` 与 `DMA_I2C_*` 的手册定义。
- 当前默认采用双向 DMA 策略：START/STOP 与超时边界仍由从机 ISR 管理，命令包主体通过 I2CR DMA 写入 `rxBuffer`，应答包通过 I2CT DMA 从 `txBuffer` 自动搬运。
- `GpLedMatrixAi8051u_SetDmaMode(context, enableRx, enableTx)` 可按方向分别开关 DMA，便于做兼容性回退或联调对比。
- 验证时除功能正确外，还要重点检查 `RXLOSS`、`TXOVW`、DMA 完成长度以及回包内容是否与协议包长度一致。

## 4. 协议包格式

每个 I2C 事务发送一个完整包：

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| `magic0` | 1 | 固定 `0x47` |
| `magic1` | 1 | 固定 `0x50` |
| `version` | 1 | 当前 `0x01` |
| `command` | 1 | 命令字 |
| `sequence` | 1 | 包序号，循环递增 |
| `flags` | 1 | 当前使用 ACK 请求位 |
| `payload_length` | 2 | Little-endian 负载长度 |
| `payload` | N | 具体命令负载 |
| `checksum` | 1 | 从包头到负载末尾的 XOR |

## 5. 当前命令集

| 命令 | 值 | 作用 |
| --- | --- | --- |
| `Ping` | `0x01` | 通链探测 |
| `SetBrightness` | `0x02` | 设置亮度 |
| `SetMode` | `0x03` | 设置播放模式 |
| `StateHint` | `0x04` | 同步小智状态 |
| `SetAction` | `0x05` | 下发颜色、图案、字模、效果等动作 |
| `FrameStart` | `0x10` | RGB332 帧传输开始 |
| `FrameChunk` | `0x11` | RGB332 分片 |
| `FrameCommit` | `0x12` | RGB332 帧提交显示 |
| `ScrollGlyphStart` | `0x20` | 字模滚动传输开始 |
| `ScrollGlyphChunk` | `0x21` | 字模滚动分片 |
| `ScrollGlyphCommit` | `0x22` | 字模滚动提交 |
| `Heartbeat` | `0x30` | 保活 |
| `Status` | `0x31` | AI8051U 回传状态 |
| `Error` | `0x7F` | AI8051U 回传错误 |

## 6. `SetAction` 动作对象

`SetAction` 负载长度固定为 18 字节，覆盖以下维度：

- `source`：本地来源或 MCP 来源
- `content`：纯色、图案、字模、状态、帧缓冲
- `effect`：静态、呼吸、渐变、滚动、淡入淡出、颜色循环
- `direction`：正常、180 度、顺时针 90 度、逆时针 90 度
- `color_mode`：纯色或渐变
- `brightness`
- 主色 `primary_r/g/b`
- 次色 `secondary_r/g/b`
- `pattern_id`、`glyph_id`
- `scroll_step`、`anim_step`、`gradient_span`
- `flags`

当前语音图像一旦下发，会保持显示，直到收到新的图像更新命令或后续显式释放命令。

## 6.1 图案预设与语音调用

当前矩阵不再自动轮播原有测试动画，而是将原有显示素材作为可调用预设：

- `diamond`：菱形图案
- `cross`：十字图案
- `JLU_emblem`：吉林大学校徽图案
- `scroll_subtitle`：滚动字幕（当前使用 AI8051U 侧内置字幕序列）
- `solid`：纯色满屏

当前行为约束：

- 指定 `diamond`、`cross`、`JLU_emblem`、`scroll_subtitle` 后，仅显示该预设，不再按旧测试逻辑在多个图案之间循环切换。
- `pulse`、`gradient` 等效果只作用在当前选中的预设图案本身，不再触发图案索引轮播。

语音控制默认行为：

- 若只说颜色，如“显示红色”，矩阵显示对应纯色满屏
- 若同时说颜色和图案，如“显示蓝色十字”“显示绿色菱形”，矩阵调用对应预设图案并应用颜色
- 若说“显示滚动字幕”或“显示红色滚动字幕”，矩阵调用内置字幕预设
- 若说“背景改成蓝色”“把背景色设为黑色”，只更新后续图案/字幕显示所使用的背景色，不改变当前纯色满屏语义

语音测试圆点联调时，ESP32 还会把同一份颜色状态同步转换为矩阵 `SetAction`：

- 未指定图案时，默认使用纯色满屏显示，不再仅通过背景色变化表达状态
- 指定 `diamond/cross/JLU_emblem` 时，矩阵调用对应预设图案
- 指定 `scroll_subtitle` 时，矩阵调用内置滚动字幕预设
- `pulse/gradient` 仅在图案预设模式下用于呼吸或渐变；纯色同步默认保持静态满屏
- 纯色显示命令不会顺带改写预设图案的背景色；背景色只由独立背景色指令或远端 `background_rgb888` 字段修改

## 6.2 当前联调日志判读

AI8051U 侧当前 USB 日志分为 4 类：

- `[I2C_INIT]`：I2C 从机初始化参数
- `[I2C_EVT] payload_stop ...`：一次带有效负载的写事务结束，已经具备进入协议解析的条件
- `[I2C_EVT] restart_flush ...`：检测到重复起始，驱动已在新的 START 到来前把前一段写入字节提交到待解析队列，用于兼容“写后 repeated-start”的事务形态
- `[I2C_IDLE] empty_stop ...`：总线上出现空 STOP 或非本从机有效写事务，属于总线背景活动，不代表矩阵协议执行成功
- `[I2C_PKT] len=... cmd=... status=...`：协议包已经真正进入解析执行；`status=0x00` 才表示该包成功

补充说明：依据 AI8051U 手册从机中断例程，`RXIF` 的首个接收字节对应的是设备地址字节而不是业务负载，驱动当前会先剥离该地址字节，再按 `GP` 协议包头解析后续字节。

正常情况下，联调应优先关注以下组合：

- `payload_stop len=10` 后紧接 `[I2C_PKT] ... cmd=0x02 status=0x00`，表示亮度设置成功
- `payload_stop len=27` 后紧接 `[I2C_PKT] ... cmd=0x05 status=0x00`，表示动作命令成功
- 若只出现大量 `[I2C_IDLE] empty_stop=...` 而没有 `[I2C_PKT]`，说明总线有活动，但最近没有形成可供 AI8051U 解析的有效矩阵协议包

## 8. 建议联调步骤

1. 上电 AI8051U，观察是否默认显示渐变流动图案。
2. 上电小智，确认调试菜单中的 `Link` 状态区先显示 `INIT / waiting image update`，且矩阵不因系统状态自动发送测试图案。
3. 通过语音触发“测试红色圆点”“测试蓝色呼吸圆点”“测试绿色渐变圆点”等命令，确认屏幕调试圆点与 LED 矩阵颜色/效果同步变化。
4. 通过语音触发“显示红色”“显示蓝色菱形”“显示绿色十字”“显示滚动字幕”等命令，确认矩阵按预设名称调用并保持显示。
5. 重复发送相同内容命令，确认 ESP32 不重复下发完全相同的动作对象。
6. 断开或关闭 AI8051U 后再次发送图像命令，确认小智侧能显示 `NO-REPLY` 或 `ERROR` 状态。
7. 如需进一步验证协议执行，可在 ESP32 侧手动发送 `SetAction`、`Frame*`、`ScrollGlyph*` 命令并记录行为。

命令示例：

- `显示红色`
- `显示蓝色菱形`
- `显示绿色十字`
- `显示白色 python 图案`
- `显示红色滚动字幕`
- `背景改成蓝色`
- `把背景色设为黑色`

## 9. 风险说明

- `lichuang-dev` 当前摄像头和矩阵链路都声明使用 `GPIO1/GPIO2`，若后续启用冲突外设，需要重新评估总线复用策略。
- 当前主机已对 `ACK_REQUIRED` 命令执行同步读回校验，但心跳超时后的自动恢复仍未补齐。
- 本次为静态实现与代码路径联通优化，尚未包含实机波形抓取和总线时序测量结果。
- 若后续抓到 AI8051U 在 `5V` 下对 `3.3V` 高电平识别不稳，应优先增加电平转换器，而不是继续单纯提高上拉强度或继续提速。
- 小智调试菜单中的 `Link` 状态区当前显示最近一次矩阵命令摘要，常见状态为 `INIT`、`ONLINE`、`NO-REPLY`、`ERROR`，并附带命令简称、序号、负载长度、回包状态和内容摘要。

# BT_Version HC-05 与 UART2 架构说明

## 1. 当前分支目标

`BT_Version` 当前分成两部分处理：

- 已实现部分：AI8051U 侧关闭原矩阵链路 I2C，改为 `UART2 + HC-05` 串口透明传输。
- 受目标能力限制部分：ESP32 侧虽已补充经典蓝牙 SPP 传输后端，但在 `ESP-IDF v5.4.3 + esp32s3` 实际链接时缺少 `esp_spp_* / esp_bt_gap_*` 符号，因此当前 `lichuang-dev` 固件不能把该后端落地为可运行映像。

因此，本分支当前完成的是 AI8051U 侧传输替换、ESP32 侧传输抽象和经典蓝牙后端预埋，以及基于实际构建结果的能力边界澄清；当前板型仍未形成“小智 -> HC-05”的可运行无线闭环。

## 2. 已实现的 AI8051U 侧结构

当前链路结构如下：

`协议包字节流 -> UART2(P4.2/P4.3) -> gp_led_matrix_ai8051u -> gp_led_action -> WS2812 显示`

关键点如下：

- 保留原有 `gp_led_matrix_protocol.h` 应用层包格式。
- 去掉原矩阵链路 I2C 从机初始化、中断和 DMA 接入。
- 改为 UART2 字节流接收，在主循环中按 `magic + length + checksum` 组包。
- 收到完整包后立即构建 `Status/Error` ACK 回包，再通过 UART2 发回。
- 上层动作执行、帧缓冲、字模传输和 WS2812 渲染路径保持不变。

## 3. AI8051U 引脚与电气设置

当前代码把 AI8051U 侧矩阵链路切换到以下引脚：

- `UART2 RX`: `P4.2`
- `UART2 TX`: `P4.3`
- `HC-05 AT/PIO11`: `P4.1`

当前初始化策略：

- `P4.2/P4.3` 均保持为准双向模式，并与已验证可工作的 `test` 工程配置对齐。
- 关闭 `P4.2/P4.3` 内部上拉。
- 关闭 `P4.2/P4.3` 内部下拉。
- 上电初始电平释放为高。
- 显式关闭 AI8051U 侧矩阵链路 I2C 外设和 DMA。

注意：

- UART 空闲态需要稳定高电平。
- 之前的开漏 TX 配置会让 `P4.3 -> HC-05 RX` 依赖外部上拉，属于 UART2 无法稳定通信的高风险点；当前已改为与 `test` 工程一致的准双向模式以避免空闲高电平悬空。
- 若实测出现空闲态不稳、波形上升沿过慢或串口乱码，应优先补充明确的外部上拉，而不是重新打开 AI8051U 内部上拉。

## 4. 时钟、UART2 与 HC-05 推荐参数

当前固件主时钟固定为：

- `33.1776MHz`

本次调整后：

- `main.c` 在系统初始化阶段显式切换到 `HIRC_33M1776()`。
- `Timer0` 重新统一为基于 `33.1776MHz` 的固定 `1ms` 调度时基。
- `test.c` 中 `Timer1` 的扫描/刷新间隔换算改为按 `MAIN_Fosc` 实时计算，避免继续沿用 `40MHz` 近似值。
- `Timer2` 仍只用于 `UART2` 波特率发生器，不能复用为其他计时功能。

当前固件默认传输串口参数：

- AT 配置阶段：`38400`
- 数据传输阶段：`115200`
- 数据位：`8`
- 校验位：`None`
- 停止位：`1`

当前流程调整为“上电自动配置 + 运行期保留调试桥”：

- AI端 在板级启动阶段先以 `38400 8N1` 完成全部 HC-05 AT 指令与查询，按“设置一条、查询一条”的顺序依次配置主机参数，并使用固定从机地址 `98:D3:02:96:A2:B1` 对应的 `AT+BIND=98D3,02,96A2B1` 完成绑定；随后才发送 `AT+RESET`，并且只有 `AT+RESET` 返回 `OK` 后，本地 UART 才切到 `115200`。
- LED端 在初始化阶段先以 `38400 8N1` 自动完成全部 HC-05 AT 指令与查询，按“设置一条、查询一条”的顺序依次配置从机参数和串口参数；随后才发送 `AT+RESET`，并且只有 `AT+RESET` 返回 `OK` 后，本地 UART2 才切到 `115200`。

当前行为保留：

- 通过 USB 串口发送结构化蓝牙调试命令：`BT SEND <text>`、`BT STATUS`，以及兼容形式 `BT <text>`。
- AI8051U 将 `BT SEND <text>` 或 `BT <text>` 中的 `text` 按 `\r\n` 结尾原样转发到 HC-05。
- 当前 AT 指令链路不再依赖 `P4.1 -> HC-05 PIO11`，即使该脚未连接，也按纯 UART AT 流程执行。
- 若发送的是 `AT+UART=<baud>,0,0`，AI8051U 会先在旧波特率下等待 HC-05 返回 `OK`，随后追加一次 `AT+RESET`；只有 `AT+RESET` 也返回 `OK` 后，本地 `UART2` 才同步切换到 `<baud>`。
- `BT STATUS` 不会向 HC-05 发数据，只会通过 USB 打印当前 UART2 波特率、AT 模式状态、发送结果、接收字节数和溢出标记。
- UART2 接收调试当前采用“中断抓取 + 调试任务处理”的方式：中断仅保存最近接收数据并置调试缓存，50ms 调试任务在检测到接收稳定后统一打印收到的文本/HEX，并对 `LED x`、`LED CLEAR` 这类文本命令执行板级 LED 控制。

## 5. Timer2 复用风险与修正

UART2 当前使用 Timer2 作为波特率发生器，因此 Timer2 不能再被 `test.c`、USB 调试逻辑或 WS2812 调试统计复用为额外的微秒计时器。

本次修正包括：

- 主运行入口重新切回 `gp_led_matrix_ai8051u -> UART2 -> gp_led_action`，移除之前为 UART1 临时验证加入的定时发送与轮询逻辑。
- 保留 `ws2812_drv.c` 中的调试钩子符号，但将其改为无副作用实现，避免再次读取或重配 Timer2。
- USB 调试路径不再提供会诱导本地状态切换的额外测试命令，减少调试逻辑与传输外设的资源交叉。

## 6. 协议变化说明

当前没有修改 `gp_led_matrix_protocol.h` 的应用层字段。

实际变化只在传输层：

- I2C 版本依赖一次事务内的完整包边界。
- UART2 版本改为持续字节流输入。
- 组包依据改为：
  - `magic0 = 0x47`
  - `magic1 = 0x50`
  - `version`
  - `payload_length`
  - `checksum`

这意味着：

- `SetBrightness`
- `SetMode`
- `SetAction`
- `FrameStart/Chunk/Commit`
- `ScrollGlyphStart/Chunk/Commit`
- `Heartbeat`

这些命令语义都保持不变，只是底层不再依赖 I2C START/STOP。

## 7. 为什么当前板型仍不能直连 HC-05

`HC-05` 是经典蓝牙 SPP 模块。当前已经在 ESP32 侧实现了矩阵传输抽象和经典蓝牙 SPP 后端代码，但在 `lichuang-dev (ESP32-S3)` 的实际构建中，链接阶段仍缺少经典蓝牙 SPP 所需符号。

约束如下：

- 当前目标仍可正常构建 BLE / Bluedroid 基础能力。
- 当前 `esp32s3` 目标在本工程和 SDK 版本下无法链接 `esp_spp_* / esp_bt_gap_*` 经典蓝牙 SPP 符号。
- `HC-05` 依赖经典蓝牙 SPP。

因此，下面这条链路在当前板型上不可实现：

`XiaoZhi ESP32-S3 Bluetooth -> HC-05`

这不是“还差少量业务代码”的问题，而是当前目标能力与 SDK 链接结果共同决定的边界。

## 8. 可继续推进的两个方向

### 方向 A：保留 `lichuang-dev`

把 `HC-05` 更换为 BLE 串口模块。

适用场景：

- 保持当前 `ESP32-S3` 板型不变。
- 后续在小智侧实现 BLE Client 或 BLE 串口适配层。

### 方向 B：保留 `HC-05`

把小智侧硬件改为支持经典蓝牙的 ESP32 芯片。

适用场景：

- 必须继续使用 `HC-05`。
- 可以接受板型更换和蓝牙栈重配。

## 9. 当前验证重点

当前分支建议先验证以下内容：

1. AI8051U 上电后是否打印 `BT_INIT`，且不再初始化矩阵链路 I2C。
2. UART2 引脚是否确认为 `P4.2/P4.3`。
3. 当前 AT 配置流程是否已完全基于纯 UART，且不再依赖 `P4.1 -> PIO11` 连线。
4. HC-05 串口参数是否与固件启动默认 `38400 8N1` 一致。
5. 通过 USB 串口命令 `BT SEND AT` 是否能把 `AT\r\n` 原样发送到 HC-05，并把响应返回到 USB 串口。
6. 通过 USB 串口命令 `BT SEND AT+VERSION?`、`BT SEND AT+ADDR?`、`BT SEND AT+NAME?`、`BT SEND AT+PSWD?`、`BT SEND AT+UART?` 是否能把 HC-05 查询结果回显到 USB 串口。
7. 通过 USB 串口命令 `BT SEND AT+UART=115200,0,0` 之后，AI8051U 是否会继续发送 `AT+RESET`，并且只有收到 reset 的 `OK` 后，本地 UART2 才切换到 `115200`。
8. USB 调试日志是否已包含 UART2 当前波特率、AT 模式状态，以及本次发送/接收是否成功。
9. 串口透明传输下，完整协议包是否能触发 ACK 回包。
10. 接收缓存溢出或长时间未收齐整包时，是否能安全丢弃当前组包。
11. 调试代码是否仍错误复用了 Timer2；当前应保证 Timer2 只由 UART2 占用。
12. 协议执行后，WS2812 动作路径是否仍与稳定版一致。
13. 文档和验证记录中是否明确写出：当前 `ESP-IDF v5.4.3 + esp32s3` 目标无法把经典蓝牙 SPP 后端链接为可运行固件。

当前 USB 调试命令说明：

- `BT SEND <text>`：主调试入口，`text` 会按 `\r\n` 结尾原样发送给 HC-05，并把接收到的响应打印回 USB 串口。
- `BT STATUS`：只打印当前 UART2 状态，不向 HC-05 发送数据。
- `BT <text>`：兼容形式，行为与 `BT SEND <text>` 相同。
- `BT SEND <text>` 的发送流程不再依赖 `P4.1` 切换 HC-05 模式，AT 指令与普通透明传输都走同一条 UART2 物理链路。
- `BT SEND AT+UART=115200,0,0` 会先等待当前指令回 `OK`，随后追加一次 `AT+RESET`；只有 reset 也回 `OK` 后，AI8051U 本地 UART2 才切换到新的波特率。
- 推荐测试序列：`BT SEND AT`、`BT SEND AT+VERSION?`、`BT SEND AT+UART?`、`BT SEND AT+UART=115200,0,0`、`BT STATUS`；其中 `BT SEND AT+UART=115200,0,0` 后应额外观察 reset 回包。
- 接收调试缓存已扩展到 `48` 字节，UART2 主接收环形缓冲扩展到 `128` 字节，USB AT 调试回包等待时间保持 `800ms`，降低 AT 配置阶段的丢包和误判风险。
- 每次发送、回包或监视输出后都会打印 `[BT_CMD]`、`[BT_RSP]`、`[BT_STA]`、`[BT_MON]`、`[BT_ACT]` 等日志，分别用于区分命令、响应、状态、监视流量和 LED 动作。

注意：

- 该命令面向 AI8051U 单侧调试，会在发送前清空当前 UART2 接收缓冲。
- AI8051U 仅做最小本地附加行为：为 HC-05 自动补齐 `\r\n` 结尾、根据是否为 `AT` 指令切换 `P4.1`、以及在 `AT+UART=...` 后同步更新本地 UART2 波特率。
